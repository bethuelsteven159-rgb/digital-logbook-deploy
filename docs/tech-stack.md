## Frontend

- **React** — builds the user interface (dashboard, entry forms, project views).
  - Chosen because the team already has direct experience with it.
- **Vite** — the build tool that runs and bundles React during development.
  - Chosen over Create React App because Vite is actively maintained (CRA is not), has a much faster dev server, and has better support for offline/PWA features, which this project needs.

## Backend

- **Node.js** — the runtime that lets JavaScript run on a server.
- **Express** — the framework used on top of Node.js to build our API (routes, request handling).
  - Chosen because the frontend and backend are deliberately separate, independent pieces. Express is the standard, well-documented choice for this in the JavaScript ecosystem, and keeps the whole stack in one language.

## Database — Offline (on-device)

- **SQLite** — a lightweight, file-based database stored locally on the user's device. Works with zero internet connection.
  - Chosen to meet the project's core offline-first requirement. The team already has working experience with SQLite (via `better-sqlite3` in an earlier lab).

## Database — Online (cloud, shared)

- **Supabase** *(pending final group confirmation)* — a hosted database (built on Postgres) that stores the permanent, shared copy of data once synced from a device.
  - Recommended over Firebase because Supabase is SQL/relational — the same data model as SQLite — which makes offline-to-online sync logic simpler than converting to Firebase's NoSQL format. Also gives the team transferable Postgres/SQL experience.

## API

- Built by hand using Express — not auto-generated by Supabase.
- Chosen so the team controls validation, security, and exactly what data is returned, rather than exposing the database structure directly.

## Testing

- **Vitest** *(pending final confirmation)* — chosen because it shares configuration with Vite (faster setup, same engine), and the team has direct prior experience with it.

## CI/CD

- **Gitea Actions** — automatically runs tests on every pull request, using our chosen Git platform (Gitea, not GitHub, so GitHub Actions does not apply).
